# Логика циклического модуля («Выбирайка»)

Этот документ описывает общую логику, по которой работает один модуль приложения. Все модули (изучение языков, спорт, домашние дела и т. д.) используют одну и ту же механику — различается только список активностей внутри модуля.

## 1. Термины

| Термин | Значение |
|---|---|
| **Модуль** | Независимая область приложения со своим циклом активностей и своим логом. Например: «Языки», «Спорт». |
| **Активность** | Один пункт цикла (например, «DE — учение слов»). Имеет текст/название и позицию в цикле. |
| **Цикл** | Упорядоченный список активностей модуля, который повторяется по кругу. |
| **Лог** | История записей вида «активность + дата» для модуля. Является источником истины: текущая позиция в цикле каждый раз вычисляется из последней записи лога, а не хранится отдельным счётчиком. |
| **Предложенная активность** | Активность, которую система показывает как следующую к выполнению. |
| **Уточнение** | Опциональный текст, привязанный к отметке выполнения конкретной активности (см. раздел 8). |

## 2. Модель данных

**Активность**
- `id` — устойчивый идентификатор (не меняется при переименовании/переносе)
- `title` — название
- `position` — порядковое место в текущем цикле

`title` не обязан быть уникальным в пределах цикла: один и тот же по названию пункт (например, «Книга») может встречаться в цикле несколько раз как разные активности с разными `id` и `position` — это разные «слоты» одного цикла. Базовый алгоритм (раздел 3) работает по `id`, поэтому повторяющиеся названия ему не мешают.

**Запись лога**
- `activityId`
- `date` — дата фактического выполнения (дата постфактум-отметки)

Лог — это плоский, только-дописываемый список записей. Ничего в логе не редактируется и не пересчитывается при изменении цикла — история выполненного остаётся как есть.

## 3. Базовый алгоритм выбора следующей активности

1. Взять последнюю запись лога модуля (по дате/порядку добавления).
2. Найти в **текущем** списке активностей модуля активность с тем же `id`.
3. Предложить следующую по `position` активность в этом списке (по кругу — после последней снова активность №1).
4. Если лога ещё нет (первое использование модуля) — предложить активность №1.

Отметка выполнения — это **действие постфактум**: пользователь отмечает «сделал это сегодня», а не получает предварительный план на день. Отметка сразу:
- создаёт запись в логе с сегодняшней датой,
- сдвигает очередь на один шаг вперёд.

Ручной выбор «не по порядку» не поддерживается — пользователю в любой момент доступна только та активность, что предложена системой согласно алгоритму.

## 4. Пропущенные дни

Пропуск дня не требует особой обработки: если пользователь не отмечал ничего несколько дней, при следующей отметке система по-прежнему предлагает ту же самую активность, которая была бы следующей — просто с более поздней датой в логе. Компенсации, «доганяния» или пропуска шагов не происходит.

## 5. Несколько отметок за один день

Ограничения на количество отметок в день нет. Пользователь может отметить несколько активностей одного модуля подряд в течение одного дня — каждая отметка независимо сдвигает очередь на один шаг и создаёт отдельную запись в логе (с одной и той же датой).

## 6. Изменение состава/порядка цикла

Пользователь может в любой момент добавить, удалить или переставить активности внутри модуля. Отдельный «указатель позиции» не хранится — при каждом вычислении следующей активности алгоритм заново ищет в **текущем** списке активность из последней записи лога (шаг 2 раздела 3) и берёт следующую по актуальному порядку.

Следствия:
- Если активность, использованная последней, была удалена из цикла — нужно правило для этого случая (см. «Открытые вопросы»).
- Перестановка активностей меняет, что будет предложено дальше, даже если лог не менялся.

## 7. Пример: модуль «Языки»

Цикл модуля:

1. DE — учение слов
2. DE — внесение слов
3. IT — учение слов
4. IT — внесение слов
5. IT — упражнения
6. FR — учение слов
7. FR — внесение слов
8. EN — учение слов
9. EN — внесение слов
10. Русский

Если последняя запись в логе — «IT — упражнения» (позиция 5), система предложит «FR — учение слов» (позиция 6). После отметки «Русский» (позиция 10) система предложит «DE — учение слов» (позиция 1) — цикл начинается заново.

## 8. Текстовое поле-уточнение (опционально для модуля)

Некоторые модули (например, «Чтение», см. `reading-module.md`) добавляют к каждой активности необязательное текстовое поле-уточнение, которое пользователь заполняет в момент отметки выполнения.

- **Поле необязательно.** Отметить активность выполненной можно и с пустым уточнением.
- **Предзаполнение — по названию активности (`title`), а не по слоту.** Если название встречается в цикле несколько раз (см. раздел 2), у всех его вхождений общий «последний введённый текст»: он ищется как уточнение из самой последней по времени записи лога с таким же `title`, независимо от того, в каком слоте цикла она была сделана.
- Открыв поле для отметки, пользователь видит это предзаполненное значение и может либо оставить его как есть, либо стереть и ввести новое — новое значение становится значением для предзаполнения при следующей встрече этого же названия.
- **В лог уточнение попадает как снимок**, то есть однажды записанная запись лога не меняется задним числом, если пользователь позже отредактирует текст для этого названия активности.

Запись лога для модулей с уточнением:
- `activityId`
- `title` — снимок названия на момент отметки
- `note` — снимок текста уточнения на момент отметки (может быть пустой строкой)
- `date` — дата выполнения
- `ts` — метка времени (используется, если модулю нужно показывать не только дату, но и время)

## 9. Открытые вопросы (требуют решения до реализации)

- **Активность из последней записи лога удалена из текущего цикла.** Что предложить дальше — активность, которая была бы следующей по старой позиции (`position` на момент удаления), или активность №1?
- **Уведомления.** Приложение только показывает предложенную активность при открытии (pull), или присылает push-напоминание, если пользователь давно не заходил?
- **Хранение и синхронизация.** Только локально на устройстве, или нужна синхронизация между устройствами/бэкап?
- **Редактирование лога задним числом.** Нужна ли возможность исправить/удалить ошибочную отметку?
